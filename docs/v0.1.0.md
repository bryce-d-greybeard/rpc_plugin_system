# v0.1.0

## Frozen goal

Prove that the kernel can securely supervise one plugin executable over Unix socket `net/rpc`.

## Scope

- kernel daemon
- Unix domain socket IPC
- Go `net/rpc`
- plugin executable contract
- test plugin executable
- heartbeat contract
- capability registration
- generation/restart IDs
- kill/restart supervision
- one-time bootstrap token startup authentication
- append-only verbose kernel event log
- small admin CLI

## Acceptance criteria

v0.1.0 is only done when all of the following are true:

1. Kernel launches the test plugin executable.
2. Plugin authenticates with one-time token bootstrap.
3. Capability registration succeeds only after successful auth.
4. `Heartbeat` works.
5. `Echo` works.
6. `Sleep` timeout is detected.
7. `Crash` or dead heartbeat is detected.
8. Kernel can kill and restart plugin.
9. Generation ID changes on restart.
10. Kernel survives plugin failure.
11. Stale-generation responses are rejected.
12. Cleanup and shutdown remove stale runtime artifacts.
13. The admin CLI reports status and can request restart.
14. Event logging is verbose, structured, durable, and human-readable enough for direct operator inspection.
15. Tests pass cleanly.

## Lifecycle rules

- one generation = one process = one socket connection = one RPC client
- process death or fatal RPC failure means generation death
- restart is replacement, not healing
- teardown must close the RPC client and socket, reap process state, remove stale artifacts, and invalidate the dead generation
- a restarted plugin must perform fresh auth, establish a fresh connection, and re-register capabilities

## Contract docs

The v0.1.0 implementation must align with:

- `docs/plugin-api.md`
- `docs/plugin-abi.md`
- `docs/compatibility.md`
- `docs/plugin-standard-v0.md`

## Validation expectation

Validation should include:

- normal `go test ./...`
- repeated acceptance and kernel restart runs
- daemon and CLI end-to-end coverage
- race-detector coverage on the supervised slice
- assertions that key lifecycle/auth/restart/timeout events are present in the event log

## Non-goals

- Postgres
- TOML note persistence
- pgvector
- gRPC
- chunking
- MCTS
